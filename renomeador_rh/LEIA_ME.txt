 RENOMEADOR RH PRO - Classic Couros - v5.0 (FASE 5)
 Guia de uso
============================================================

O QUE ESTE PROGRAMA FAZ
------------------------------------------------------------
Le os documentos digitalizados do RH (PDF, JPG, PNG), descobre
com Inteligencia Artificial o nome do funcionario, o tipo do
documento e a data, e entao:
  - RENOMEIA no padrao  NOME_IDENTIFICADOR_TIPO_DATA.ext
    (ex.: JOAO DA SILVA_CPF900_HOLERITE_2026-05.pdf)
  - ARQUIVA na pasta certa (por tipo e por ano/mes)
  - monta o DOSSIE de cada colaborador
  - alimenta uma BASE DE DADOS e gera RELATORIOS + PAINEL
  - (opcional) ENVIA o documento para a Convenia

------------------------------------------------------------
COMO ABRIR
------------------------------------------------------------
1. Duplo clique em  INICIAR.bat
2. Se faltar Python, ele abre o site para instalar. MARQUE
   "Add Python to PATH" na instalacao e rode o .bat de novo.

------------------------------------------------------------
CONFIGURACAO (campos da tela)
------------------------------------------------------------
- Chave Gemini (obrigatoria): gratis em aistudio.google.com/apikey
- Chave Claude (opcional): reserva paga, console.anthropic.com
- Token Convenia (opcional): para cadastro via API e envio
- Pasta origem: onde estao os documentos a renomear
- Pasta destino: a raiz do RH (as subpastas sao criadas sozinhas)
- Cadastro: lista oficial de colaboradores (botao XLSX ou API)
- Intervalo: espera entre arquivos (6 a 30s; 10s recomendado)

Caixas de selecao:
- Mover (nao copiar): se marcado, TIRA o arquivo da origem.
  Na duvida, deixe DESMARCADO (copia, mantem o original).
- Modo teste (5 arquivos): processa so 5. Use na primeira vez.
- Ler nome do arquivo antes de usar IA (gratuito): se o proprio
  nome do arquivo ja tiver nome+tipo (ex.: "FERIAS CHELI PAULA.pdf"),
  renomeia SEM gastar IA. So scanner (BRW...) e nomes incompletos
  vao para a IA. Esses aparecem como PROVEDOR "Nome do arquivo".
- Agrupar por colaborador (dossie): cria COLABORADORES/NOME - ID/
  com uma copia de cada documento da pessoa.
- Enviar para Convenia (FASE 5): apos renomear, envia o documento
  para a ficha do colaborador (precisa token + cadastro pela API).

------------------------------------------------------------
BOTOES
------------------------------------------------------------
INICIAR (verde)   -> comeca.
PAUSAR/RETOMAR    -> pausa e continua.
PARAR (vermelho)  -> interrompe.
Validar           -> testa o token da Convenia.
Testar Chaves     -> testa Gemini e Claude (use antes de iniciar).
XLSX / API        -> carrega o cadastro (planilha ou API Convenia).
Reprocessar falhas-> roda de novo SO o que deu ERRO, ficou PENDENTE
                     (_REVISAR) ou saiu com confianca BAIXA.

DICA-CHAVE: SEMPRE carregue o cadastro antes de iniciar. Com ele,
o nome lido pela IA e trocado pelo NOME OFICIAL (corrige OCR),
casa por CPF, e quem nao for encontrado vai para _REVISAR.

------------------------------------------------------------
COMO OS ARQUIVOS SAO ORGANIZADOS
------------------------------------------------------------
Por ano/mes:
  HOLERITE      -> HOLERITES / 2026 / 06-Junho
  RECIBO        -> RECIBOS / 2026 / 06-Junho
  ADIANTAMENTO  -> ADIANTAMENTOS / 2026 / 06-Junho
  CARTAO PONTO  -> CARTÃO PONTO / 2026 / 06-Junho
Por ano:
  13 SALARIO    -> 13 SALARIO / 2026
Atestado separado por dias (regra do INSS):
  ATESTADO / Ate 3 dias
  ATESTADO / 4 a 15 dias
  ATESTADO / 16+ dias (INSS)
  (meio periodo vai para "Ate 3 dias" e o nome leva "_meio-periodo")
Pasta unica:
  ACORDO DE COMPENSAÇÃO, PLANO ALIANÇA, FERIAS, RESCISAO
  (rescisao/aviso previo), DDS, PORTABILIDADES,
  DOCUMENTOS 2025 (contrato/admissao), OUTROS.
Duvidosos:
  _REVISAR  -> confianca BAIXA, nao identificado, ou fora do cadastro.
  O arquivo e COPIADO com o nome original; o original continua na
  origem; fica PENDENTE. Ao resolver e rodar de novo (ou Reprocessar),
  ele e arquivado certo e a copia em _REVISAR e removida sozinha.

ATENCAO LGPD: ATESTADO e o dossie contem dados de saude. O programa
NAO coloca diagnostico/CID no nome. Restrinja o acesso a essas pastas.

------------------------------------------------------------
DOSSIE POR PESSOA (com "Agrupar por colaborador")
------------------------------------------------------------
  COLABORADORES / NOME - ID /   -> funcionarios ATIVOS
  DESLIGADOS    / NOME - ID /   -> funcionarios DESLIGADOS
O desligamento e detectado pela data no cadastro do Convenia OU por
um documento de RESCISAO. Quando isso ocorre, a pasta da pessoa e
movida de COLABORADORES para DESLIGADOS. Os documentos ficam em dois
lugares (na pasta por tipo e no dossie).

------------------------------------------------------------
BASE DE DADOS E RELATORIOS  (pasta "_RELATORIOS RH")
------------------------------------------------------------
A cada rodada o programa atualiza, dentro de <destino>\_RELATORIOS RH\:
  - historico_rh.csv -> base unica, acumula entre as rodadas e NAO
    duplica (reconhece o arquivo pelo conteudo).
  - documentos_por_tipo_mes.csv
  - atestados_por_mes.csv (com faixas ate 3 / 4 a 15 / 16+ INSS)
  - absenteismo_por_colaborador.csv (ranking por dias)
  - pendencias_documentos.csv (ativos sem holerite/recibo do mes)*
  - checklist_admissao.csv (admitidos ult. 120 dias)*
  - checklist_desligamento.csv (desligados ult. 180 dias)*
  - painel_rh.html -> PAINEL VISUAL (abra com 2 cliques, funciona
    offline): indicadores, atestados por mes, ranking de absenteismo
    e pendencias.
  - relatorio_renomeacao_AAAAMMDD_HHMMSS.csv -> resultado da execucao
    (original, novo nome, pasta, provedor, status, confianca, convenia).
  (*) precisam do cadastro carregado.

------------------------------------------------------------
RETOMADA, EQUIPE E SEGURANCA
------------------------------------------------------------
- Retomada: se fechar no meio, ao reabrir ele pergunta se quer
  continuar de onde parou (nao refaz o que ja deu certo). O progresso
  fica na pasta destino (_renomeador_progresso.json), compartilhavel.
- Um de cada vez: enquanto alguem processa, o programa cria uma trava
  (_renomeador_EM_USO.lock) na pasta destino. Outra pessoa ve
  "Sistema em uso por Fulano - aguarde". A trava sai sozinha ao fim.
- Credenciais:
    * Ficam salvas POR COMPUTADOR em %LOCALAPPDATA%\RenomeadorRH,
      CIFRADAS com a conta do Windows (DPAPI) - nao viajam para outro PC.
    * Alternativa em equipe: coloque um arquivo ".env" (modelo em
      .env.exemplo) ao lado do programa, com GEMINI_KEY, CLAUDE_KEY e
      CONVENIA_TOKEN. Ao abrir, os campos sao preenchidos sozinhos.
      NUNCA versione o .env no Git (ja esta no .gitignore).

------------------------------------------------------------
PERGUNTAS COMUNS
------------------------------------------------------------
> "Limite atingido (429)": normal no plano gratuito. O programa
  espera e tenta de novo; apos 3 falhas troca para o Claude (roxo)
  e a cada 5 min tenta voltar ao Gemini.
> Erro 401 ao validar Convenia: token invalido/expirado - peca um
  novo token no painel da Convenia.
> Dois arquivos com o mesmo nome: adiciona _1, _2, etc.
> Precisa instalar algo alem do Python? Nao.
